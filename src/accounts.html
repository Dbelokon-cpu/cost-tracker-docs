A cost account groups work for cost purposes: capitalised versus operating spend, a client, a cost centre. Unlike a Jira custom field, an account is defined by a JQL filter, so no field has to be added to your issues.

What an account holds

FieldNotes
Name and KeyBoth must be unique across the site.
CategoryBillable, Capitalized (CAPEX), Operating (OPEX) or Other.
JQLWhich issues belong to the account. It is checked when you save it.
Cost rate, Billing rateOptional hourly rates for work on the account's issues. They can start on a date; see Rates that change over time.
Lead, Customer, ContactOptional descriptive fields.
StatusOpen or Closed. Informational: it filters the list but does not switch the account off.

How an account is applied to a project

  • For each project, the account's JQL is combined (AND) with the project's own scope, and the matching issues are found in the same scan that computes the report.
  • An account's rate applies to work on its issues. It beats a role's rate and the project default, but not a person's own rate.
  • An issue that matches more than one account goes to the account created first, so every worklog has exactly one rate.
  • If an account's JQL later stops being valid (a deleted field, for example), the account is skipped rather than breaking the report.
  • Account rates are plain numbers applied as-is in each project's own currency. There is no conversion.
  • Expenses can be booked to an account, which is how the Overview's Accounts card and the "by account" report split cost.

Who can manage accounts

Accounts are site-wide setup, like attributes and the role library. Only Jira site administrators can create, edit or delete them; everyone can see them. Accounts are managed under Setup → Accounts, with a switch between Accounts and Customers views.

You can create up to 20 accounts, because each one costs an extra Jira search every time a project is calculated.
