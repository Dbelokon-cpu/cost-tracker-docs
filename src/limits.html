If a project is over 500 issues

The 500-issue limit is deliberate, sized for small and medium teams. A bigger scope still works, but only the first 500 issues count and the page says so (Overview, Scope and Reports all show the warning, with the real size when Jira can tell). To get complete figures:

  • Split by Jira space. If the scope covers several spaces, make one cost project per space and group them in a portfolio.
  • Narrow by period. Add a date condition to the JQL, for example AND created >= "2026-01-01", and keep a separate project for older work.

Behaviour

TopicHow it behaves
CurrencyA property of each project. Amounts are never converted. A portfolio or report adds money only across projects with the same currency.
RatesNon-negative numbers. Empty means "use the next level", 0 is a real rate. A rate can start on a date; with no date it applies to all hours.
Worklog dateThe day the worklog was logged for, as Jira stores it. Rates are matched to this date.
Type or currency changeNothing is converted; the app asks you to confirm first.
Date formatShown in Jira's own style, for example Oct 22, 2026. Typed dates also accept YYYY-MM-DD.
ReportsRead Jira live (not cached) for the chosen timeframe.
ExportsXLSX files, generated from what is on screen. CSV export was removed.
Jira dataOnly read, never changed. See Privacy.
