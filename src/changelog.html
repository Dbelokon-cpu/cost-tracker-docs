October 2026

11 October

  • Rates can change over time. Every rate (a person's, a role's, a cost account's and the project default) can now start on a date. Hours logged before the date keep their old rate, so a raise no longer reprices past months. Each period records who set it and when, and a history window lists them. Leaving the date empty works as before: the rate applies to all hours. See Rates that change over time.
  • "Hourly rates are not set" banner. Overview, Team and Revenue now say when logged time is counted at 0 only because no rate applies yet.
  • Confirmation before changing a project's type or currency. The window explains that nothing stored is converted.
  • Clearer limit warning. When a project has more than 500 issues, the page now shows "first 500 of about N issues" and how to split the project.
  • The portfolio Timeline tab was removed; a portfolio now has Summary and Configuration tabs.
  • Portfolio pages show their cards and member projects straight away and fill in figures as each project finishes calculating.
  • People pickers no longer list app accounts.
  • Attributes attach to specific projects and appear only on those.

9 October

  • Cost Tracker is now only on the global Apps page. It no longer appears inside individual Jira projects.
  • The Projects table appears at once and fills in its financial columns row by row, so a slow project never blocks the page.

8 October

  • Reports reworked into a list of saved reports, a read-only result view and an edit form. Editing a saved report now updates it instead of risking a duplicate.
  • People search auto-triggers after two letters, with no Search button.
  • This documentation site, privacy policy and security policy were published.

1 October

  • Recurring expenses can repeat every N months and stop at the project's end date, a specific date or after a number of occurrences.
  • Dates use Jira's own style, for example Oct 22, 2026.
  • Export to XLSX replaced the old copy-and-paste CSV export, on expenses, fixed revenue, portfolios and reports.

Late September 2026

  • Portfolio access: portfolios are private to their owner and can be shared with named people as read-only viewers.
  • Transfer ownership: a project owner can hand a project to someone else and stays on as an editor.
  • Site-wide setup (accounts, attributes, role library) can be changed only by Jira site administrators.
  • Revenue tab, fixed revenue entries and a portfolio Configuration tab.
